# SproutBook 3.2.0: everyday routines, potty journal, milk freezer
Extend the verified native 3.1.0 app. Kotlin, Compose, minSDK26, targetSDK37, package com.nothatcher.sproutbook. No new dependencies, no WebView. Preserve records, local signing identity and caregiver mutation guard.

Routines: child-owned title, selected weekdays (Monday=bit0), optional time, responsibility/owner label, notes, pause toggle. Separate dated completions with a unique routine/day, undo and history. Today shows today's active routines, with open-to-complete access. Routines remain available for every stage; never delete history when a child's stage changes. Native editor, weekday chips, Android time picker, daily date selector, edit/delete confirmation. Completion is a parent action; no rewards, scoring or penalties.

Potty: neutral Tried/Wet/Dirty/Mixed/Accident observations with recorded time and notes. Quick wet/dirty buttons and dated manual entry, editing/deletion, paged history. Today toddler shortcut, Care all-stage access. No targets, diagnoses or promises about readiness.

Milk freezer: individual containers with label, pumped/stored time, original volume (canonical mL), location and notes. Frozen/Used/Discarded history; inventory shows frozen total/container count and oldest first. Optional saved Pump session creates a container once using that session's total, by transaction with fresh identity checks. No feed automatically created when marking used: storage use does not mean feeding. Terminal status records retain original volume and allow notes only. Dirty drafts cannot mark used/discarded until saved. No computed expiration, storage duration advice or medical safety assessment.

Data: Room schema11 adds routines, routineCompletions, pottyLogs, milkContainers with child FK cascade and parent links. Backup version3 adds these four strict tables, accepts complete version1 (14 tables) and version2 (17 tables) by filling missing new tables, preserves current version's full key validation. Validate enums, finite volumes, times, owner/child links, completion uniqueness and pump link uniqueness/kind. Diagnostics reflects actual new schema/table counts. Grandparent mode hides/disables every mutation and repository independently enforces it.
